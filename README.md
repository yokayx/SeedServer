# SeedServer

Готовая заготовка Minecraft Java-сервера на Folia 26.3 с вращением миров на разных сидах.

## Что умеет

- Слушает Java-клиентов на TCP-порту **25566**; серверная дальность прорисовки — **32 чанка** (simulation distance — 8).
- При первом запуске берёт основной мир как стартовый, затем заранее создаёт следующие миры с уникальными случайными 64-битными сидами.
- Постепенно генерирует вокруг спавна каждого подготовленного мира квадрат 9×9 чанков. Миры и очередь сохраняются между перезапусками.
- Команда **`/next seed`** переносит всех игроков в следующий подготовленный мир.
- После перехода сид показывается всем игрокам в чате; клик по числу копирует его в буфер обмена клиента Minecraft. При входе игрок тоже видит сид активного мира.
- Все игроки принудительно остаются в креативном режиме.
- Плагин использует global-, region- и entity-schedulers Folia и помечен как поддерживающий Folia.
- Прошлые миры сохраняются в `data/`, поэтому данные можно изучить или восстановить вручную.

## Запуск

Нужен Docker с Docker Compose и доступ к сети для загрузки Folia и Folia API при первой сборке.

1. Скопируйте пример настроек:

   ```sh
   cp .env.example .env
   ```

2. Прочитайте Minecraft EULA по адресу <https://aka.ms/MinecraftEULA>. Если вы принимаете её условия, поменяйте в `.env` `EULA=FALSE` на `EULA=TRUE`.
3. Соберите и запустите сервер:

   ```sh
   docker compose up -d --build
   ```

4. Подключитесь к `АДРЕС_СЕРВЕРА:25566`. Данные сервера находятся в `./data/`.

Следить за запуском и остановить сервер можно так:

```sh
docker compose logs -f minecraft
docker compose down
```

Чтобы открыть сервер для внешних игроков, разрешите TCP-порт **25566** в firewall и пробросьте его на машину с Docker.

## Использование

`/next seed` по умолчанию доступна операторам (`seedserver.next`, default `op`) и консоли. Выдать право отдельному игроку можно через систему permissions, например LuckPerms. Вызов команды из игры переносит **всех находящихся онлайн** игроков в следующий мир.

В начале сервер подготавливает два мира в очереди. Если команда вызвана до окончания генерации первого, сервер сообщит, что нужно подождать, и не будет переключать игроков на неподготовленную карту. После смены мира очередь пополняется автоматически.

## Настройка подготовки миров

После первого запуска отредактируйте `data/plugins/SeedServer/config.yml`, затем перезапустите контейнер:

```yaml
warm-worlds: 2
pregeneration-radius-chunks: 4
chunks-per-tick: 1
```

- `warm-worlds` — число будущих миров в очереди (от 1 до 5).
- `pregeneration-radius-chunks` — радиус области вокруг спавна; значение `4` генерирует 9×9 чанков. Генерация всего бесконечного мира заранее невозможна: новые чанки будут появляться по мере исследования.
- `chunks-per-tick` — скорость генерации; увеличивайте осторожно, чтобы не перегружать CPU.

Seed и список ожидающих миров хранятся в `data/plugins/SeedServer/state.yml`. Не удаляйте активный мир или миры из очереди при работающем сервере. Старые карты не удаляются автоматически и со временем занимают место на диске.

## Сервер и плагин

- Folia / Minecraft Java **26.3**; для сборки используется `dev.folia:folia-api` с версией из официального диапазона Folia 26.3.
- JVM 25 (образ `itzg/minecraft-server:java25`).
- Основные настройки Compose находятся в `compose.yaml`; серверный порт в этом проекте намеренно зафиксирован на `25566`.
- Плагин собирается из `plugin/` внутри Docker-образа, отдельно устанавливать его не нужно.

## Ограничение Folia

Folia 26.3 существует; для плагинов нужна зависимость `dev.folia:folia-api`, а не `io.papermc.paper:paper-api`. В этой сборке API используется в официально указанном Folia диапазоне `[26.3.build,)`, а миры/игроки обрабатываются через schedulers Folia.

При этом README Folia помечает загрузку и выгрузку миров как проблемную область API: [Folia 26.3 README](https://github.com/PaperMC/Folia/blob/ver/26.3.x/README.md#current-broken-api). SeedServer создаёт следующие миры динамически, поэтому после успешной сборки обязательно проверьте несколько вызовов `/next seed` на настоящем Folia 26.3. Если сам сервер отклоняет динамическую загрузку мира, это ограничение Folia, а не ошибка разрешения Maven-зависимости.
